# scripts/

- **`fencingapi.py`** — Frank's fencing-api client (AskFRED / USA Fencing / FencingTracker). Key via `FENCING_API_KEY` in gitignored `.env`. See **SOURCES.md § fencing-api**.
- **`askfred.py`** — AskFRED API helper for Clark Kent's gather (epee near Chatham). Key via `ASKFRED_API_KEY` / gitignored `.env`. See **SOURCES.md § AskFRED API**.
- **`build_budget_html.py`**: builds the standalone budget page. Each build is numbered per week: `budget-demo/out/budget-no-<N>-<date>-v<K>.html`, with the counter and Frank's decision log in `staging/weeks/<pile>/budget-versions.json`. A rebuild with unchanged data keeps the number. The page starts from the latest captured decisions and shows "Budget vK · decisions captured through <time ET>". `--preview` builds an unnumbered copy. The build refuses while a dropped submission is un-ingested (`--allow-pending` to override). See **budget-demo/STANDALONE-README.md**.
- **`ingest_budget_submission.py <file> [--dry-run]`**: records a budget-page submission. It applies the vets to `items.json` and appends the decisions (including optional `pages` / `resize` / `layout` / `mode` / `manualLayout`) to `budget-versions.json`. Overlaps or overset in a manual layout are warnings, never silently fixed; unvetted includes still refuse (exit 4). Always dry-run first, apply, then rebuild for the next version.
- **`record_chat_decision.py --at <ISO> --text "<Frank's words>" [--include/--exclude SLOT] [--after SLOT=PREV] [--answer SLOT Q A] [--change "..."] [--dry-run]`**: logs budget decisions Frank gives in chat as the next decision in `budget-versions.json` (source `chat:frank:<time>`, his words verbatim). It carries the previous decision's page state forward and applies the slot changes, so the next build seeds the page correctly; the item/lineup edits themselves are made separately. Dry-run first, then rebuild.
- **`budget_page/`**: the Budget page's UI, inlined by `build_budget_html.py`: `page.html`, `page.css`, `core.js` (logic; runs under node for tests), `ui.js` (DOM), `layouts.json` (which slots can switch Wide/Tall; variant names shared with compose/), `calibration.json` (fitted capacity numbers; generated). `pageVersion` is `budget-paper-v2`. Auto placement is the default; Manual freezes the layout so Frank can drag, resize and drop blocks onto the bank himself.
- **`budget_model.py`**: the capacity model in Python (same arithmetic as `costOf()` in `core.js`); merges `calibration.json` over `lineup.capacity`.
- **`build_section_history.py [--check] [--explain]`**: derives which registry section ran in which published issue (`site/issues.json` + `issues/<date>/`), using `section_history_rules.json`. Writes `scripts/section-history.json`; `publish_issue.py` refreshes it at publish time and `build_budget_html.py` derives a fresh copy for every budget page.
- **`tests/`**: frozen inputs in `scripts/tests/fixtures/` (No. 7 lineup + a pointer at the archived `staging/weeks/2026-11-17` pile, plus a section-history snapshot through No. 6) so a later roll of `staging/weeks/next` cannot break them. Live staging and submissions are never touched. Run:
  - `python3 scripts/tests/test_budget_page.py` — builder, submission contract, ingest, capacity model (node; no Chrome)
  - `python3 scripts/tests/test_section_history.py` — derived history vs the frozen audit (no Chrome)
  - `python3 scripts/tests/test_budget_interactions.py` — headless Chrome, real pointer events, including Manual placement (skipped without Playwright or Chrome)
  - `python3 scripts/tests/smoke_budget_chrome.py PAGE.html [SCREENSHOT_DIR]` — optional Chrome smoke check
